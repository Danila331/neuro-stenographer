# real — реальные записи пользователя

Самый ценный набор: единственный, который близок к тестовым записям жюри. Нужно 3–6 записей по 2–5 минут.

## Как записывать

- **2–4 человека**, разговор свободный (можно разыграть «диалог котиков»: заседание в Котовице, протокол, мяуканье).
- **2–5 минут** на запись; лучше 5–6 записей разного типа:
  1. **звонок** — быстрая речь, короткие реплики, перебивания; запись на громкой связи или с двух телефонов;
  2. **встреча** — телефон/диктофон лежит на столе, говорящие на разном расстоянии (farfield);
  3. хотя бы одна запись с **фоном** (кухня, улица, вентилятор, музыка);
  4. хотя бы одна запись с **частыми перебиваниями** и короткими «да / угу / ага / ну / нет».
- Записывать **штатным диктофоном телефона** (m4a/aac, mp3, amr, ogg, wav — любой формат; импорт сам сконвертирует).
- Говорить естественно; не читать по бумаге ровным голосом. Часть реплик — короткие (1–2 слова), несколько чисел и дат.
- Не называть реальные ФИО, телефоны и адреса: записи могут попасть в отчёты. Для себя — на ваше усмотрение, но данные остаются локально (`.cache/data/real`).
- Перед записью договоритесь, кто какой «спикер»; в ручной разметке метки любые (А, Б, Иван).

## Импорт

```bash
cd src/eval/datasets
.venv/bin/python real/import_audio.py ~/rec/meeting1.m4a ~/rec/call1.amr --speakers 3 --notes "диктофон на столе, кухня"
# → $ROOT/.cache/data/real/{audio_orig,audio,ref,annotation}/ и manifest.csv (condition=real, annotated=0)
```

Конвертация: ffmpeg (системный или из PyPI `imageio-ffmpeg`), 16 кГц mono PCM16; если ffmpeg недоступен — `soundfile` (wav/flac/ogg/mp3).
Оригинал сохраняется в `audio_orig/`. Сплит — `--split dev|test` или стабильный хэш (≈ 30 % test).
Записи со сплитом `test` для подбора параметров не используем.

## Разметка

1. Черновик из гипотезы пайплайна (формат выхода: `{"transcript":[...]}`; JSON выдаёт пайплайн другого агента):

```bash
.venv/bin/python real/make_draft_ref.py /path/to/hyp/meeting1.json meeting1
# → annotation/meeting1.txt (для правки) и ref/meeting1.draft.json
```

2. Откройте `annotation/<id>.txt`, слушая запись, и **исправьте на слух**: текст (что реально сказано, слово в слово, без «причёсывания»), границы реплик, говорящих, добавьте пропущенные реплики и коротенькие «угу». Формат строки:

```
[MM:SS.mmm - MM:SS.mmm] метка: текст реплики
```

- метка — любая (`А`, `Иван`, `speaker_2`); при сборке нумеруется `speaker_1..N` по порядку первого появления;
- перекрывающиеся реплики — отдельные строки с пересекающимися временами;
- `start` — начало первого слова, `end` — конец последнего (не границы паузы);
- числа пишите так, как произносят (словами) — если нет иной договорённости для WER-нормализации;
- строки с `#` — комментарии. Время можно без миллисекунд: `[01:02 - 01:09]`.

3. Сборка эталона и проверка правил (docs/team/ARCHITECTURE_TEAM.md §1: speaker_N по первому появлению, целые мс, сортировка, времена в пределах длительности):

```bash
.venv/bin/python real/compile_ref.py meeting1        # → ref/meeting1.json, annotated=1 в manifest.csv
.venv/bin/python -m stenodata validate real
```

Рекомендация: делайте эталон за два прохода (первый — тексты, второй — границы по пикам речи), а метки времени проверяйте
по спектрограмме/волне в любом редакторе (Audacity: метки → экспорт `MM:SS.mmm`).
