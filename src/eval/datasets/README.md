# stenodata — eval-датасеты для «Нейро-стенографиста»

Скрипты, которые собирают наборы для подбора моделей и параметров по цифрам (WER, DER, метки времени).
Всё складывается в общий кэш `$ROOT/.cache/data/<имя>/` в формате `docs/team/ARCHITECTURE_TEAM.md` §2:

```
<name>/manifest.csv        id,audio,ref,duration_ms,num_speakers,lang,source,condition,split[,доп. колонки]
<name>/audio/<id>.wav      16 кГц mono PCM16
<name>/ref/<id>.json       {"transcript":[{"speaker_id":"speaker_1","start_ms":..,"end_ms":..,"text":".."}]}
<name>/STATS.md            статистика датасета
```

`split`: `dev` (≈70 %) / `test` (≈30 %, **не трогаем при подборе параметров**). Сплит — стабильный хэш от id
исходной фразы/сценария (искажённые варианты одной фразы и все озвучки одного сценария попадают в один сплит).

## Датасеты

| имя | что | источники |
|---|---|---|
| `ru-asr-dev` | одиночные фразы с эталонным текстом для сравнения ASR (+ искажённые варианты) | FLEURS ru, VoxForge ru, Golos (crowd, farfield), RuLS |
| `ru-dialog-synth` | диалоги 2–4 **реальных** дикторов (1–5 мин), собранные по модели очерёдности | VoxForge ru (диктор = username/сессия), RuLS (диктор = reader id) |
| `ru-dialog-tts-cats` | 40 сценариев «котиков» (Котовица, заседание, протокол), озвученные локальным TTS. **Слабый прокси**: голоса слишком чистые и различимые | Piper ru_RU (denis, dmitri, irina, ruslan) + macOS `say` Milena (если есть) |
| `en-asr-dev` | одиночные английские фразы (второй язык), `lang=en` | LibriSpeech test-clean / test-other, FLEURS en dev |
| `en-dialog-synth` | английские диалоги 2–3 реальных дикторов (LibriSpeech), условия clean / noise / farfield (+ phone в call), `lang=en` | LibriSpeech |
| `ru-en-mixed` | 5 диалогов 3–4 дикторов: русские (VoxForge/RuLS) + реальный(е) англоязычный(е) диктор(ы) LibriSpeech — проверка определения языка, `lang=ru+en`, колонка `lang_segments` | VoxForge, RuLS, LibriSpeech |
| `real` | структура и инструменты для реальных записей пользователя (см. `real/README.md`) | ваши записи |

### Колонки manifest (сверх docs/team/ARCHITECTURE_TEAM.md §2)

| колонка | где | смысл |
|---|---|---|
| `condition` | все | `clean` \| `noise` \| `reverb` \| `overlap` \| `phone` \| **`farfield`** \| `real` (farfield — расширение контракта, см. ниже) |
| `scenario` | dialog-наборы | **`meeting`** — встреча в умеренном темпе; **`call`** — быстрый разговор (звонок) |
| `condition_detail` | все | JSON: параметры (SNR и тип шума, RT60 и размеры комнаты, расстояния/усиления дикторов, кодек, ускорение, профиль пауз) |
| `overlap_frac` | dialog-наборы | доля длительности записи, где одновременно звучат ≥ 2 реплик (по эталону) |
| `license` | все | лицензии исходных данных |
| `lang` | все | `ru` / `en` / `ru+en` |
| `lang_segments` | ru-en-mixed | JSON: язык каждой реплики (по исходному диктору) |
| `overlap_trans` | dialog-наборы | доля смен говорящего, при которых следующая реплика начинается до конца предыдущей |
| `speakers_src` / `voices` / `script` | synth / tts | исходные дикторы / голоса TTS и питч / id сценария |
| `ref_style`, `speaker`, `gender`, `orig_id` | ru-asr-dev | `punct_case` (пунктуация и регистр: FLEURS, VoxForge, RuLS) / `lower_nopunct` (Golos) / `upper_nopunct` (LibriSpeech); исходный id |
| `annotated`, `notes` | real | размечена ли запись |

### Условия (`condition`)

- `clean` — без обработки; общий комнатный шум-пол −58…−48 дБ маскирует различие «фонов» исходных записей.
- `noise` — MUSAN music (OpenSLR 17, `music/fma`, часть корпуса), ESC-50 (в т.ч. класс «cat» — мяуканье; классы с речью/смехом исключены), babble (речь других дикторов) или розовый шум; **SNR 5–20 дБ** к активной речи.
- `reverb` — синтетические RIR (pyroomacoustics, ShoeBox, RT60 0.25–0.9 с); у каждого говорящего своя позиция; прямой путь выровнен — метки не смещаются.
- `phone` — полоса 300–3400 Гц, 8 кГц, кодек через ffmpeg (opus 8/12k, mp3 16k, g726, µ-law; в 30 % комбинируется с шумом), назад в 16 кГц; задержка кодека компенсируется кросс-корреляцией.
- `overlap` — чистый звук, но до 55 % смен говорящего с перекрытием 0.5–3 с (в `call` — 50 % и 0.2–1.8 с); фактическая доля — в `overlap_frac`.
- `farfield` — **диктофон на столе**: переговорная с RT60 0.3–0.8 с, дикторы в разных точках (0.5–5 м), громкость −3…−15 дБ относительно ближнего, постоянный фон вентиляции (SNR 15–25 дБ). Равная доля с остальными (в `meeting` — 1.5×). В `ru-asr-dev` так помечены записи Golos farfield (реальная дальнепольная речь).
- `real` — реальные записи пользователя.

### Сценарии (`scenario`)

- `meeting`: паузы между репликами −400…+900 мс, перекрытия ≈ 12 % смен говорящих; условия: clean, noise, reverb, overlap, farfield (чаще), phone (реже).
- `call`: время-растяжение 1.1–1.25× без изменения тона (ffmpeg `atempo`), паузы короче (30–600 мс), перекрытий ≈ 25 % смен; ≈ 45 % файлов с телефонным кодеком, остальное clean/noise/overlap/reverb.
- Файлы чередуются `meeting`/`call` — объём примерно поровну.

### Как строятся диалоги (ru-dialog-synth)

1. Выбираются 2–4 разных диктора; каждая реплика — реальная запись фразы этого диктора.
2. С обеих сторон реплики обрезается тишина энергетическим VAD (порог адаптивный: 10-й перцентиль энергии + 9 дБ / пик − 32 дБ), нормализуется активный уровень (−26 дБFS), затем диктору добавляется своё усиление (−6…+3 дБ).
3. Очерёдность: следующий говорящий ≠ предыдущего (в 18 % случаев тот же), пауза/перекрытие — из профиля; позиция реплики определяется паузой относительно **конца предыдущей реплики**.
4. Эталонные `start_ms`/`end_ms` — позиции вставки обрезанных реплик (границы речи). Реверберация и кодеки не сдвигают метки (проверяется тестами).
5. Тексты — как в источнике (с пунктуацией и регистром, если они есть); числа в сценариях TTS записаны словами (как произносятся).

## Запуск

```bash
cd src/eval/datasets
./make_all.sh                 # скачать исходники (если нет в .cache/data/.raw) и собрать всё (RU + EN + mixed)
./make_all.sh --quick         # маленькая версия
./make_all.sh --n-asr 800 --n-synth 60 --n-tts 80 --seed 1 --skip-fetch

# по частям
.venv/bin/python -m stenodata fetch voxforge golos        # источники → $ROOT/.cache/data/.raw/<name>/
.venv/bin/python -m stenodata build asr synth tts en-asr en-synth mixed --seed 0 \
    --n-asr 600 --n-synth 36 --n-tts 60 --n-en-asr 220 --n-en-synth 14 --n-mixed 5
.venv/bin/python -m stenodata validate                    # проверка форматов (docs/team/ARCHITECTURE_TEAM.md §1–§2)
.venv/bin/python -m stenodata stats --update-readme       # статистика → STATS.md и этот README

# тесты
.venv/bin/python -m pytest -q
```

Окружение: `uv venv --python 3.11 .venv && uv pip install --python .venv/bin/python -e .`
(`make_all.sh` делает это сам). ffmpeg берётся из PyPI-пакета `imageio-ffmpeg` (или `FFMPEG=/path/to/ffmpeg`).
Нагрузка: каждый шаг сборки однопоточный (BLAS=1 поток, onnxruntime=1, ffmpeg `-threads 1`); запускайте не более трёх процессов сразу.
Переменные: `STENO_ROOT` (корень репозитория), `STENO_DATA` (каталог данных), `STENO_RAW` (каталог исходников).

**Детерминированность:** все случайные решения идут из `rng_for(seed, имя, индекс…)`; один и тот же `--seed` и те же исходники дают тот же результат (проверено тестом `tests/test_builders.py::test_build_dialogs_deterministic_and_valid`: два прогона дают побайтно одинаковые WAV; на другой версии ffmpeg/libopus кодеки `phone` могут дать иной битовый результат). TTS-голоса Piper детерминированы при фиксированных `noise_scale`, `say` — системный.

## Известные слабости

- **Дикторы.** Для русского нет свободного корпуса с ID дикторов и *диалогами*. VoxForge/RuLS — чтение книжных предложений, а не разговор: нет эмоций, перебиваний «по смыслу», междометий. Реплики не связаны по смыслу.
- **Бэкчаннелы** («да», «угу», «ага», «ну», «нет») реальных дикторов с известной личностью найти не удалось (Golos без ID дикторов). В реальной части их нет; в `ru-dialog-tts-cats` короткие реплики есть (озвучка TTS, говорящий известен).
- **Утечка канала.** У каждого диктора свой микрофон/шум записи → диаризация по «каналу» проще, чем в реальной записи с одним микрофоном. Смягчено общим шум-полом, `reverb`/`farfield` (общая комната), но не устранено.
- **TTS** — чистые, хорошо различимые голоса; питч-сдвиг создаёт «варианты» одного голоса, у них близкие эмбеддинги.
- **Перекрытия** собираются суммированием сигналов, без эффектов Ломбарда/реальной интонации перебивания.
- **ru-en-mixed:** смена языка происходит только на границе реплик/говорящих (каждый реальный диктор говорит на одном языке); внутриречевого code-switching (русская фраза с английскими словами одним голосом) нет.
- Женских голосов в VoxForge мало (≈ 11 % реплик), в RuLS test — 4 из 7 дикторов женские; 328 «дикторов» VoxForge включают анонимные сессии (одна сессия = один диктор; один человек мог записаться дважды — внутри одного диалога сессии разных username/дат берутся как разные люди).
- Тексты VoxForge/RuLS — литературные (поэзия в RuLS test); Golos — команды голосовому ассистенту; лексика далека от «диалогов котиков».
