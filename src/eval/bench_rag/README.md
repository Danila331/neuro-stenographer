# bench_rag — B50 «Выжимка» и B51 «AI-поиск»: исследование и прототип на ПК

Python-эталон (Python 3.11, `uv`, `pytest`) + спецификация порта в Android: **`ANDROID_SPEC.md`**. Промпты и GBNF — `prompts/android/` (см. `README.md` там же).
Данные: настоящий выход пайплайна `refpipe-medium-relabel` (ASR+диаризация, с ошибками) и эталоны cats; сценарии cats задают темы. Все замеры — M3 Pro, CPU, **4 потока**, load average 7–12 (секунды ориентировочные, относительные); «телефон» = пересчёт по множителям `bench_llm/README` (prefill ×2.4, decode ×3.8, якорь Galaxy S23 Ultra) — **оценка, не замер на устройстве**.

## 2. Выжимка (B50)

**Алгоритм (map-reduce, `summary.py`, `segment.py`):**
1. *Фрагменты* ≤ 1500 симв. (≈ 650 токенов) режутся **по долинам косинуса** между окнами из 3 реплик (векторы реплик — те же, что индекс поиска, лишней модели нет); минимум 3 реплики и 300 симв.
2. *Map:* один вызов LLM на фрагмент = одна тема → JSON по **GBNF**, собираемой под фрагмент: ссылки только на существующие номера, пункт говорящего K может цитировать **только строки K** (чужую строку сгенерировать нельзя); `refs` идут перед `text` (модель сначала «читает» цитату).
3. *Проверка* (`validate`): говорящий пункта = говорящий цитируемых реплик; пункт отбрасывается, если основы слов не покрыты цитатой (пункты < 0.3, решения/задачи < 0.5); при слабой ссылке — перепривязка к реплике, которая это действительно говорит; иначе пункт выкидывается.
4. *Reduce:* склейка соседних тем с похожими заголовками (Жаккар основ ≥ 0.45), дедуп пунктов, время темы — из реплик; `overview`.

## 3. AI-поиск (B51)
**Корпус и вопросы:** «история» = 40 записей cats (455 реплик пайплайна / 631 эталонных); 58 вопросов с эталонными репликами (`questions.py`, золото — подстрока эталонной реплики, на выходе пайплайна сопоставляется по времени): 18 про говорящего («что говорил говорящий N про …», N берётся из эталонных меток), 4 про переименованного («Тихон», «Василий Петрович»), 16 про тему в записи, 20 по всей истории. В ASR-корпусе 2 вопроса без ответа (пайплайн потерял реплику) — исключены (n = 56). Метрики на уровне чанка: чанк верен, если содержит эталонную реплику; recall@5 — доля эталонных реплик в топ-5 (при 1–2 эталонных ≈ hit@5), MRR@10. Оговорка: окна крупнее реплики, поэтому hit@5 у `win*` выше «по построению» — модели сравниваем в одном режиме; различия < 0.05 на 56 вопросах (20 «по истории») — шум.

**Конвейер:** чанки (реплика / ход / окно) → BM25 (Snowball + обрезка основы до 5 символов, стоп-слова и слова вопроса вроде «говорил», «обсуждали» не участвуют) ∥ плотный поиск (косинус) → RRF → фильтр говорящего (`speaker_N`, «говорящий 2», «второй спикер», имя из переименования — из запроса вырезается).

**Рекомендация: ObjectBox** (HNSW, cosine, `dimensions = 384`, f32) за интерфейсом `VectorStore`; в `:core` держим `BruteForceVectorStore` (int8 + переранжирование f32) как тестовую реализацию и запасной путь для lite/при проблемах с лицензией или 16 КБ. Обоснование: единственный вариант, который одновременно (1) даёт именно *векторную БД* с персистентностью, (2) имеет зрелый Kotlin-API и Maven-артефакты, (3) держит 10⁵ векторов с запросом < 1 мс. Для реальных историй (≤ 10⁴ чанков) перебор тоже укладывается в десятки мс — выбор ObjectBox это не про скорость, а про готовую БД и запас на рост; цена — закрытый бинарь и +2–6 МБ.

## 5. Риски и ограничения
* **Малая и синтетическая выборка:** сценарии cats озвучены TTS, 58 вопросов (из них 20 «по истории»), 11 документов — различия < 0.05 в поиске и < 0.1 в выжимке не значимы; окна завышают hit@5 «по построению»; живых встреч и оценки читателем нет. Золото выжимки лексическое: оно награждает дословность (extractive).
* **Качество 1.7B:** проверка убирает 36 % пунктов, оставшиеся иногда искажены (задачи, сроки); полнота решений/задач 0.64, исполнитель 0.33, тезисы по говорящим 0.37. Показывать как «черновик» с переходом к репликам. `overview` пока копирует заголовки.
* **Скорость на телефоне — оценка** (множители 2.4/3.8 из `bench_llm`, якорь Galaxy S23 Ultra), не замер; ПК был под нагрузкой (load 7–17).
* **ObjectBox:** закрытая нативная часть («temporary» лицензия по FAQ), плагин Gradle GPL-3 (сборка), 16 КБ-страницы — проверить `llvm-objdump -p`; запасной `BruteForceVectorStore` за тем же интерфейсом.
* **Эмбеддинги:** ONNX USER2-small получен нашим экспортом (torch, opset 17, int8 per-channel; cos к sentence-transformers 0.99, потерь качества нет) — собирается один раз, на устройстве ModernBERT-граф не запускали; запасной вариант без конверсии — e5-small (официальный int8). Токенайзер (BPE) надо переписать на Kotlin с паритет-тестом по `tokenizer.json`.
* **Вход пайплайна:** ASR теряет часть ответов (2 из 58 вопросов), дробит фразы («8», «400», «₽»), диаризация ошибается → `merge_turns`, окна, мягкий фильтр говорящего.
* **Не сделано:** замеры на устройстве; ORT-Android; усечение словаря e5 (250k → ~30k, 112 → ~45 МБ); LLM-судья/живая оценка выжимки; FTS5 (в Android SQLite нет).
* Для разработки: `llama-server` b12177 зависает, если не читать `stderr` (embedding-режим писал по строке на запрос) — в JNI не относится.
