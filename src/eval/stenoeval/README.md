# stenoeval — оценка качества «Нейро-стенографиста»

Python-пакет и CLI для проверки формата JSON, подсчёта WER / cpWER / DER / JER / точности временных
меток / RTF и ведения таблицы прогонов `artifacts/test-results/results.csv`.
Методика жюри заранее неизвестна, поэтому ключевые метрики считаются **в нескольких вариантах**
(режимы нормализации текста, величины collar). Главные показатели для сравнения вариантов —
**микро-усреднённые WER `norm` (без знаков препинания) и WER `punct` (знаки и регистр учитываются, е=ё)**:
по ответам жюри (docs/team/BACKLOG.md Q13/Q14) пунктуация, по всей видимости, входит в WER, а различие е/ё не считается.
Какая именно токенизация знаков у жюри, неизвестно, поэтому считаются три punct-режима.

## Установка

```bash
cd src/eval/stenoeval
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -e ".[dev]"
.venv/bin/stenoeval --version
.venv/bin/pytest -q                      # 78 тестов
```

Зависимости: numpy, scipy (венгерский алгоритм), rapidfuzz (быстрый Левенштейн; без него — чистый
Python, но медленнее), num2words, jsonschema, pyannote.core + pyannote.metrics. Сеть нужна только
для установки. `meeteval` не используется — cpWER реализован самостоятельно (определение совпадает).

## Команды

### `stenoeval validate <file.json>... [--duration-ms N]`
Строгая проверка по docs/team/ARCHITECTURE_TEAM.md §1 и `config/transcript.schema.json`. Код возврата 1, если хоть один
файл не прошёл. Проверяется: валидный UTF-8 без BOM; нет дубликатов ключей и `NaN`/`Infinity`;
кириллица не записана `\uXXXX`; ровно ключ `transcript` и ровно 4 ключа у реплики; `start_ms`/`end_ms`
— настоящие целые (`true` и `1.0` не принимаются); `speaker_N`, N ≥ 1, нумерация по первому
появлению; `0 ≤ start_ms < end_ms` (и `≤ duration_ms`, если задан); сортировка по
`(start_ms, end_ms)`; `text` непустой, без крайних пробелов и переводов строк. Пересечения реплик
разрешены; `{"transcript":[]}` валиден.

### `stenoeval score --dataset <root> --run <run_dir> [опции]`
Формат датасета и прогона — docs/team/ARCHITECTURE_TEAM.md §2: `<root>/manifest.csv`, `<root>/ref/<id>.json`;
`<run_dir>/<id>.json` (+ `<id>.meta.json` с `processing_ms`, `tier`, `config_hash`, `device`,
опционально `num_threads`).

| опция | смысл |
|---|---|
| `--run-id` | по умолчанию имя папки `--run` |
| `--tier --device --num-threads --notes` | перекрывают/дополняют поля из meta; `--platform desktop\|android` (по умолчанию desktop) |
| `--split dev\|test\|all`, `--ids a,b` | фильтры по manifest (test не использовать при подборе параметров) |
| `--only-present` | пропустить файлы без гипотезы. **По умолчанию файл без гипотезы считается пустой расшифровкой** (WER 100 %), с предупреждением |
| `--csv PATH` | дописать строки в results.csv (заголовок создаётся, колонки фиксированы); повтор `run_id` → ошибка, `--replace` заменяет |
| `--json-out PATH` | полная детализация по файлам: все режимы нормализации, все collar, компоненты DER, S/D/I |
| `--commit`, `--dataset-name` | перекрыть `git rev-parse HEAD` / имя папки датасета |

Печатает сводную таблицу: ALL и по каждому `condition`. Невалидная по ТЗ гипотеза всё равно
оценивается, но помечается (`flag=invalid_hyp` в notes, предупреждение в stderr); нечитаемый JSON =
пустая гипотеза (`unparseable_hyp`).

### `stenoeval compare <results.csv> --run-ids a,b[,c] [--tol 0.002] [--fail-on-regression] [--markdown]`
Первый прогон — базовый. Сравниваются только файлы, присутствующие во всех прогонах. Печатает метрики
и дельты (в п.п., мс), построчно WER по файлам и вердикт `OK / REGRESSION`: регресс, если у WER norm,
WER raw, cpWER или DER рост больше `--tol` (абсолютная доля; 0.002 = 0.2 п.п.). С
`--fail-on-regression` код возврата 1 — правило «точность не ухудшается» для скриптов.

### `stenoeval report <results.csv> --out docs/TEST_RESULTS.md [--run-ids a,b] [--summary-only]`
Markdown: сводка по прогонам, затем для каждого прогона таблицы по условиям и по файлам.

### Формат `notes` в results.csv
Колонки CSV не менялись. В конец `notes` добавляется машинный блок `[refw=… werr=… …]`:
счётчики слов/ошибок и секунд DER, по которым `compare`/`report` считают **точный микро-WER и
микро-DER** из одного CSV (`refw/werr` — norm, `*_raw`, `*_num`, `*_hy`, `*_p` — punct, `*_ps` — punct_sep, `*_pl` — punct_lc, `cperr` — cpWER norm,
`dtot/derr` — секунды DER при collar 0, `dtot_c/derr_c` — при collar ±0.25 с (NIST), `tsn` — число реплик
с найденными метками, `ts_acc300`). Свой текст идёт перед блоком. Строки, добавленные другими
инструментами без блока, агрегируются средним по файлам.

## Определения метрик

### Нормализация текста (`stenoeval/textnorm.py`)
Токены — слова, разделённые пробелами после нормализации.

| режим | что делает |
|---|---|
| `raw` | `text.split()`, ничего не меняется: регистр, пунктуация, `ё` значимы |
| `norm` | NFKC → lower → `ё→е` → убрать знак ударения (U+0301) → всё, что не буква/цифра, → пробел → split. **Дефис и любые тире — разделители:** «кто-то» → «кто то», «Ёлки-палки» → «елки палки». Выбор симметричен для эталона и гипотезы; так делает базовый нормализатор Whisper; снимает неоднозначность «кто-то»/«кто то» (стоила бы 2 ошибок) |
| `norm_hy` | как `norm`, но дефис между двумя буквами/цифрами сохраняется: «кто-то» — одно слово. Контрольный вариант |
| `punct` | знаки и регистр **сохраняются**; только NFKC, `ё→е`/`Ё→Е`, схлопывание пробелов. Знаки приклеены к словам, как в `raw`: «день!» — один токен, «день !» — два |
| `punct_sep` | как `punct`, но каждый знак препинания (категория Unicode `P*`) — отдельный токен: «день!» → «день», «!»; «да» в кавычках → «, да, »; «...» → три токена «.» (NFKC раскрывает «…»). Остаются внутри слова: дефис/тире между двумя буквами или цифрами («кто-то») и `,`/`.` между цифрами («3,5»). Регистр сохраняется |
| `punct_lc` | как `punct_sep`, в нижнем регистре |
| `norm_num` | `norm` + числа цифрами → слова по-русски (num2words, lang=ru) до удаления пунктуации: «25» → «двадцать пять», «3,5» → «три запятая пять», «1990» → «тысяча девятьсот девяносто», «5-й» → «пятый», «10-15» → «десять пятнадцать» |

Ограничения `norm_num`: падеж/род/число угадать нельзя — числа всегда в именительном, порядковые
(суффикс `-й`, `-го`, …) — в мужском роде им. падежа («в 1990 году» → «… девяносто году», а человек
напишет «девяностом»); `%` и валюта — пунктуация; цифры, слитые с буквами («5кг»), дают «пять кг»;
числа длиннее 18 цифр читаются по одной цифре. Поэтому `norm_num` — оценка «в пределах возможного»,
если жюри нормализует числа; если эталон жюри содержит цифры, а наша выдача слова (или наоборот), в
`norm` это будет ошибкой, в `norm_num` — нет (кроме падежных расхождений).

### WER
`WER = (S + D + I) / N` по Левенштейну на словах (rapidfuzz; эквивалент jiwer). Реплики **всех**
спикеров склеиваются по порядку `(start_ms, end_ms)` (при равенстве — порядок в файле), спикеры
игнорируются. `N` — число слов эталона; при пустом эталоне знаменатель 1 (каждое вставленное слово
= 1.0), пустой эталон и пустая гипотеза = 0. **Микро-усреднение** (сумма ошибок / сумма слов по
файлам) — главный показатель в сводке; среднее по файлам (`wer_norm_macro`) хранится отдельно.
Колонки CSV: `wer_raw` = режим `raw`, `wer_norm` = `norm`; остальные режимы (`punct`, `punct_sep`,
`punct_lc`, `norm_num`, `norm_hy`) — в машинном блоке `notes`, в сводной таблице (`WER punct`,
`WER p-sep`, `WER p-lc`, `WER num`) и в `--json-out`. `score` печатает строку
`MAIN (micro): WER norm = … WER punct = …`. `compare` считает регрессом ухудшение WER norm, **WER punct**,
WER raw, cpWER, DER.

### cpWER
Для каждого спикера эталона и гипотезы реплики склеиваются по `start_ms`. Спикеры эталона
сопоставляются с различными спикерами гипотезы венгерским алгоритмом так, чтобы суммарное число ошибок
было минимальным (ID спикеров не важны, переставленные ID не штрафуются). Спикер эталона без пары —
все его слова удаления; лишний спикер гипотезы — все его слова вставки. Колонка `cpwer_norm` — режим
`norm` (в `--json-out` ещё `raw`, `norm_num` и `punct`).

### DER, JER, число спикеров
`pyannote.metrics` (`DiarizationErrorRate`, `JaccardErrorRate`, `skip_overlap=False` — **перекрывающаяся
речь оценивается**). Сегменты — реплики целиком `[start_ms, end_ms]` (включая паузы внутри реплики:
пословных меток нет); перекрывающиеся реплики одного спикера объединяются. Карта оценки
`[0, max(длительность, последний конец)]` — ложные тревоги вне речи эталона считаются. Соответствие
спикеров — венгерский алгоритм (оптимальное).
- `der` = collar 0; `der_collar` = классический NIST/DIHARD collar ±0.25 с вокруг границ эталона
  (решение архитектора). **Внимание:** в pyannote параметр `collar` — полная ширина окна, поэтому
  ±0.25 с = `collar=0.5` (`der.nist` в `--json-out`). Вариант `collar=0.25` (±0.125 с) оставлен только
  в `--json-out` (`der.c025`). В сводке колонка называется `DER ±.25`.
- В сводке DER микро-усреднён (сумма секунд ошибок / сумма секунд речи эталона), JER — среднее по файлам.
- Эталон без речи, гипотеза без речи: DER = 0; эталон без речи, гипотеза с речью: DER не определён
  (пустая ячейка; секунды ложных тревог всё равно входят в микро-DER). Гипотеза без речи при непустом
  эталоне: DER = JER = 100 %.
- Точность числа спикеров = доля файлов, где `num_speakers_hyp == num_speakers_ref`
  (`spk acc`); `spk_mae` = среднее |разницы|. `num_speakers_ref` берётся из manifest, при его отсутствии — из эталона.

### Точность временных меток (`stenoeval/timing.py`)
1. Токены эталона (режим `norm_num`) помнят номер своей реплики.
2. Времена слов гипотезы: если рядом с `<id>.json` лежит **`<id>.full.json`** (расширенный экспорт,
   `{"utterances":[...]}` или экспорт приложения `{"transcript":[...]}`; у каждой реплики поля
   `start_ms`, `end_ms`, `text`, `words:[{"text","start_ms","end_ms"}]`), берутся
   настоящие пословные времена (слово, нормализующееся в несколько токенов, делит свой интервал по длине).
   Реплика без `words` и вообще отсутствие файла — запасной вариант: время реплики **распределяется по
   словам пропорционально длине слова в символах** (паузы не моделируются). Какой вариант использован,
   записывается в `notes`: `ts=words` / `ts=utt` (при непригодном `.full.json` — предупреждение и `ts=utt`).
   Остальные метрики (WER, DER) всегда считаются по `<id>.json`.
3. Глобальное выравнивание Левенштейна последовательностей слов эталона и гипотезы.
4. Для каждой реплики эталона берутся выровненные слова гипотезы (точные совпадения; если их нет —
   подстановки). Предсказанный `start` = начало самого раннего, `end` = конец самого позднего.
5. `ts_start_mae_ms`, `ts_end_mae_ms` — среднее |Δ| в мс по репликам эталона, у которых нашлось хоть одно
   слово (в сводке усредняется с весом числа таких реплик). `start<300ms` — доля **всех** реплик
   эталона с |Δstart| < 300 мс (ненайденные считаются промахом; для `end` то же в `--json-out`).
Если первое слово реплики эталона пропущено распознаванием, начало «съезжает» на следующее слово — это
часть метрики.

### RTF
`rtf = processing_ms / duration_ms`; `processing_ms` из `<id>.meta.json`, `duration_ms` — из
manifest (иначе из WAV, иначе конец последней реплики эталона). В сводке `RTF` = `Σ processing_ms /
Σ duration_ms`; `rtf_mean` — среднее по файлам. Замеры на ПК — относительные.

## Быстрая проверка на фикстурах
```bash
.venv/bin/stenoeval score --dataset tests/fixtures/dataset --run tests/fixtures/run_noisy --json-out /tmp/d.json
.venv/bin/stenoeval score --dataset tests/fixtures/dataset --run tests/fixtures/run_perfect --csv /tmp/r.csv
.venv/bin/stenoeval score --dataset tests/fixtures/dataset --run tests/fixtures/run_noisy   --csv /tmp/r.csv
.venv/bin/stenoeval compare /tmp/r.csv --run-ids run_perfect,run_noisy
.venv/bin/stenoeval report  /tmp/r.csv --out /tmp/r.md
```
Фикстуры: `cat01` обычный диалог, `cat02` перекрытия и 3 спикера, `cat03` один спикер с числами,
`cat04` пустой эталон; `run_perfect` = эталон, `run_noisy` — без пунктуации, потерян спикер, числа
словами, галлюцинация на тишине.
