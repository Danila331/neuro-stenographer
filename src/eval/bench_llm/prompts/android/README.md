# Промпты LLM для приложения (протокол и вопросы)

Финальные версии. Формат -- обычный текст в ChatML без «размышлений» (ровно то, что собирает `PromptBuilder.chatml`),
сэмплинг greedy (как в `llm_jni.cpp`). Проверены на Qwen3-1.7B Q4_K_M; Qwen3-0.6B для этих задач непригоден (см. `../../README.md`).

## Что заменить в `src/android/app/src/main/assets/prompts/`

| Файл здесь | Куда | Назначение |
|---|---|---|
| `protocol_system.txt` | `protocol_system.txt` | «Протокол заседания»: Резюме / Вопросы / Решения / Поручения / Цитаты, в пунктах время `[мм:сс]` |
| `protocol_notes_system.txt` | `protocol_notes_system.txt` | конспект фрагмента (используется только текущим конвейером «конспект -> протокол»; при переходе на слияние в коде не нужен) |
| `qa_system.txt` | `qa_system.txt` | «Вопрос по расшифровке»: 1–2 предложения, говорящий и время, «В расшифровке этого нет» |

Контракт с кодом не меняется: `Prompts.kt` читает те же три файла, `PromptBuilder.clean` убирает `**` и теги.
Формат строк расшифровки -- как сейчас: `[мм:сс] Говорящий N: текст`.

## Предложения по коду (необязательные; измерено в `../../README.md`)

1. **Длинные записи: протокол по фрагментам + слияние в коде вместо «конспект -> протокол по конспектам».**
   Для каждого фрагмента (бюджет `contentBudgetChars(nCtx, 450, system)`) вызвать тот же `protocol_system.txt`
   (max 450 токенов), затем объединить разделы детерминированно: `Резюме` -- склейка резюме фрагментов; `Вопросы/Решения/Поручения/Цитаты` --
   конкатенация пунктов, дубликаты (по нормализованному тексту) и «нет» отбросить. Эталон: `bench_llm/android_flow.py: split_sections, merge_protocols`
   (~30 строк). На 5 диалогах подряд (1180 слов), n_ctx 2048: полнота фактов 0.69 против 0.19 у «конспект -> протокол»; время 63 с против 88 с (M3, 4 потока).
   Причина: 1.7B теряет структуру на втором (сводном) проходе и копирует реплики.
2. **Фильтр цитат**: удалить из протокола пункты «Цитаты» с `«...»`, которых нет в расшифровке дословно (`norm` из ARCHITECTURE §6). Без него дословны ~50% цитат
   (1.7B), с ним -- 100% оставшихся (эталон `filter_quotes`).
3. **Вопросы по длинной записи**: резать на фрагменты не по всему контексту, а по ~1/4 бюджета (сейчас `chunk(lines, budget)` даёт 2–3 крупных куска, и `selectRelevant`
   выбирает один из них, ~3000 токенов на запрос: 40 с на M3, ~2 мин на телефоне). С мелкими фрагментами в запрос попадёт ~1000 токенов.
4. Таймкоды: модель иногда пишет время не из строки расшифровки (~10%); можно заменить на ближайшее существующее время начала реплики.
