# bench_llm -- выбор локальной LLM (llama.cpp) для протокола и вопросов

Что это: стенд для замера малых GGUF-моделей на русских задачах после основной обработки: «Протокол заседания» и «Вопрос по расшифровке»
(воспроизводит поток `LlmController`/`PromptBuilder` приложения). Ранее исследовались пунктуация и исправление спикеров через LLM -- от этого
отказались (пунктуацию ставит ASR); результаты остались в `results/punct`, `results/diarfix` (см. раздел «Побочные результаты»).

## Установка и запуск
```
cd src/eval/bench_llm
uv venv --python 3.11 .venv && uv pip install --python .venv/bin/python -e ".[dev,baseline]"
# llama.cpp (тег b12177, CPU-only, без Metal/Accelerate), вне git:
git clone --depth 1 --branch b12177 https://github.com/ggml-org/llama.cpp .build/llama.cpp
PATH=$PWD/.venv/bin:$PATH cmake -S .build/llama.cpp -B .build/llama.cpp/build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DGGML_METAL=OFF -DGGML_ACCELERATE=OFF -DGGML_BLAS=OFF -DLLAMA_CURL=OFF
PATH=$PWD/.venv/bin:$PATH cmake --build .build/llama.cpp/build -j6 --target llama-server llama-bench llama-quantize
.venv/bin/python -m pytest -q                                         # 6 passed
# качество протокола/вопросов (модели из $ROOT/.cache/models/llm/):
.venv/bin/python -m bench_llm.run_android_flow --model app-qwen3-1.7b-q4_k_m --prompts prompts/android --n-ctx 4096 --tag t1 \
    --sets d1_budget d2_bridge d3_holiday long [--merge] [--flags=-nr]
.venv/bin/python -m bench_llm.run_mem --models app-qwen3-1.7b-q4_k_m --ctx 2048 4096 --flags=-nr --tag _B   # пиковая память
scripts/mem_matrix.sh app-qwen3-1.7b-q4_k_m                           # матрица флагов памяти
.venv/bin/python -m bench_llm.run_speed --models app-qwen3-1.7b-q4_k_m --threads 4 --repack 0 --tag _rp0   # llama-bench
```
Данные: 5 моих русских диалогов `data/dialogs/` (d1–d3 заседания, d4–d5 бытовые), `data/protocol_gold.json` (ключевые факты и вопросы), `long` = все 5 подряд (1180 слов).
Автопроверки: полнота фактов (ключевые слова решений и поручений), существующие таймкоды, дословность цитат, придуманные имена, верность ответов (ключевое слово).

## Результаты (M3 Pro, CPU-only, 4 потока, greedy; машина была нагружена другими задачами, load 5–20, поэтому секунды ориентировочные)

### Качество (финальные промпты `prompts/android/`, n_ctx 4096; d1/d2/d3)
| Модель | Полнота фактов | Дословные цитаты | Вопросы верно | Придуманные имена |
|---|---|---|---|---|
| Qwen3-0.6B Q4_0 (промпты v4) | 0.17 / 0.60 / 0.20 | 0/2, 2/3, 2/3 | 1/4, 2/4, 2/4 | копирует пример (Иван, Забор) |
| Qwen3-1.7B Q4_K_M | 1.00 / 1.00 / 0.80 | 1/2, 0/3, 1/2 | 4/4, 4/4, 3/4 (v4) | 0–2 (флексии имён) |
| Qwen3-1.7B Q4_0 (мой квант из Q8_0) | 0.67 / 0.80 / 0.80 | 1/2, 1/2, 0/2 | 4/4, 4/4, 4/4 | 0–3 |
| Qwen3-4B Q4_K_M (v4) | 1.00 / 1.00 / 0.80 | 3/3, 3/3, 2/2 | 3/4, 4/4, 4/4 | 0–1 (в одном протоколе 8 слов-заголовков) |

Флаги памяти (`-nr`, KV q8_0) на качество не влияют: полнота 1.00 / 1.00 / 0.80 во всех трёх конфигурациях.
Длинная запись (1180 слов): n_ctx 2048 -- «конспект -> протокол» 0.19, слияние в коде 0.69; n_ctx 4096 -- оба 0.50 (слияние вдвое быстрее: 44 с против 102 с).
Промпты v1 -> v5: v1 (шаблон с заглушками) модель переписывала буквально («тема [мм:сс]»); пример с реальным содержанием из другой темы убирает это; имена в примере модель копирует (убраны).

### Память (пиковая за запрос на ~85% контекста; RSS macOS включает файловые страницы mmap, «footprint» -- только анонимную/грязную память)
| Модель, файл | Флаги | RSS 2048 / 4096, МБ | footprint 2048 / 4096, МБ |
|---|---|---|---|
| Qwen3-1.7B Q4_K_M, 1282 МБ | по умолчанию (repack) | 2358 / 2583 | 1361 / 1587 |
|  | `-nr` | 1558 / 1783 | 311 / 536 |
|  | `-nr`, без mmap (`-lm none`) | 1560 / 1784 | 1531 / 1754 |
|  | `-nr`, KV q8_0 | 1455 / 1575 | 208 / 328 |
|  | `-nr`, без mmap, KV q8_0 | 1455 / 1575 | 1425 / 1545 |
| Qwen3-1.7B Q4_0, 1054 МБ | по умолчанию / `-nr` + KV q8_0 | 2559 / 1358 (4096) | 1536 / 328 (4096) |
| Qwen3-0.6B Q4_0, 429 МБ | по умолчанию / `-nr` + KV q8_0 | 1181 / 739 (4096) | 833 / 305 (4096) |
| Qwen3-4B Q4_K_M, 2497 МБ | по умолчанию | 5173 / 5462 | 2781 / 3071 |
|  | `-nr` + KV q8_0 | 2679 / 2833 | 272 / 427 |
Причина: на arm64 llama.cpp перепаковывает веса (repack) в отдельный буфер рядом с mmap -- это +1 ГБ RSS у 1.7B (приложение измерило PSS ~2.2 ГБ). `-nr` убирает копию.
KV на токен: 1.7B ~112 КБ (f16), 4B ~147 КБ.

### Скорость (llama-bench, 4 потока, pp512 / tg64 tok/s; load ~10–12)
| Модель | repack | `-nr` | `-nr` + KV q8_0 |
|---|---|---|---|
| Qwen3-1.7B Q4_K_M | 178 / 57 | 89 / 50 | 77 / 37 |
| Qwen3-1.7B Q4_0 | 265 / 60 (в тихие минуты 355 / 90) | 86 / 48 | -- |
| Qwen3-0.6B Q4_0 | 652 / 214 | 243 / 83 | -- |
| Qwen3-4B Q4_K_M | 64 / 18 | -- | -- |
Выше -- время на M3 (эмулятор на ARM-хосте ближе к нему). Реальный телефон: публичный якорь llama.cpp issue #26957 (Galaxy S23 Ultra, Snapdragon 8 Gen 2, CPU, Qwen3.5-2B Q4_K_M 1.3 ГиБ):
decode ~14 tok/s, prefill 65–73 tok/s; для 1.7B Q4_K_M (1.19 ГиБ) это ~15 / ~76 tok/s, то есть в 2.4 раза медленнее по prefill и в 3.8 по decode.

Время «Протокола» одной записи (Qwen3-1.7B Q4_K_M, repack): ~1500 токенов запроса (~2.5 мин речи) и ~330 токенов ответа -- 14–17 с на M3 (измерено при малой нагрузке), ~40 с на телефоне (оценка).
Запись 30 мин (~16 тыс. токенов, 5 фрагментов по слиянию): ~2 мин на M3, ~5–6 мин на телефоне (оценка). Вопрос по короткой записи: 5–9 с на M3.

## Рекомендации `llm.*`
| tier | llm.model | n_ctx | флаги | Комментарий |
|---|---|---|---|---|
| lite (APK <= 0.8 ГБ) | нет (`null`), `summary: false` | -- | -- | Qwen3-0.6B не справляется с протоколом и вопросами (факты 0.06–0.6, вопросы 1–2 из 4, копирует пример). Кнопки LLM скрыть с пояснением |
| medium (<= 1.6 ГБ) | `llm/qwen3-1.7b-q4_k_m.gguf` (1282 МБ) | 4096 (на 4 ГБ можно 2048 при слиянии в коде) | `-nr` (в `llama_model_params`: repack off), KV q8_0 + flash attention; mmap включён | пик RSS 1.58 ГБ (footprint 0.33 ГБ), prefill вдвое медленнее, качество то же. Если места в APK не хватает: Q4_0 (1054 МБ), но полнота ниже (0.67–0.8) |
| hard (<= 3.5 ГБ) | `llm/qwen3-4b-q4_k_m.gguf` (2497 МБ) | 4096 | `-nr` + KV q8_0 (RSS 2.8 ГБ) на 8 ГБ устройстве можно и с repack (5.4 ГБ) | дословные цитаты, полнота 1.0/1.0/0.8, но в 3–4 раза медленнее 1.7B (~40 с на M3, ~2.5 мин на телефоне на протокол 2.5-минутной записи) |
В `-nr` заметна цена: время запросов растёт ~1.5–2 раза. Если по памяти заведомо хватает (>= 3 ГБ свободно), repack быстрее. Выбор делает приложение по свободной памяти.

## Побочные результаты (отменённые направления; цифры предварительные, на малой выборке)
* Пунктуация: RUPunct-small (ONNX int8, 29 МБ) F1 знаков 0.86 (FLEURS) / 0.66 (диалоги), RUPunct-medium int8 0.88 / 0.74; Qwen3-0.6B с грамматикой слов 0.75 / 0.58; Qwen3-4B 0.84 (FLEURS). Свободная генерация LLM меняет слова в 40% случаев (0.6B).
* Исправление спикеров 0.6B ухудшает (110 ошибочных слов -> 164), эвристика «привязка к концу предложения» даёт 110 -> 32.
