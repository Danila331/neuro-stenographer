# Quiet Spruce Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Привести весь нативный Android UI к спокойной современной системе из `design.md`, сохранив функциональность, стабильные подписи, `testTag`, экспорт и обработку аудио.

**Architecture:** Сначала заменяем Compose‑токены и общие примитивы, затем перестраиваем экраны по типам Workbench, Long Document и Narrative Workflow. Бизнес‑логика, навигация и контракты данных не меняются; доступность и адаптивность проверяются на реальном Android‑устройстве.

**Tech Stack:** Kotlin, Jetpack Compose, Material 3, Gradle, JUnit 4, Compose UI Test, ADB.

---

## Этапы

1. **Токены и регрессионные проверки**
   - Добавить JVM‑тесты на новые значения палитры, контраст, радиусы и типографику.
   - Запустить их до реализации и убедиться в ожидаемом FAIL.
   - Обновить `Color.kt`, `Accent.kt`, `Theme.kt`, `Type.kt`.

2. **Базовые компоненты**
   - Переработать `Primitives.kt`: тонкие границы, отсутствие жёстких теней, современные кнопки, chips, switch, progress, slider и fields.
   - Обновить `Common.kt`: top bar, dialogs, sheets, snackbars и section rows.
   - Сохранить публичные Compose API и семантику доступности.

3. **Экраны**
   - Главная: ясный сценарий создания расшифровки и спокойная история.
   - Расшифровка: документ вместо набора тяжёлых карточек; компактные AI‑инструменты и плеер.
   - Обработка и запись: прогресс, текущая стадия, живой текст без лишних контейнеров.
   - Протокол, выжимка, поиск, модели, настройки, статистика, лицензии и online setup — единая система.
   - Обновить launcher icon и ресурсы без изменения package name.

4. **Сборка и проверка**
   - Запустить новые тесты и существующие JVM‑тесты приложения и core.
   - Собрать точный debug APK.
   - Запустить на совместимом Android‑устройстве через ownership‑aware helper.
   - Снять светлую и тёмную темы, основные рабочие экраны, шрифт ×1,6 и альбомную ориентацию.
   - Исправить визуальные дефекты и повторить проверку.

5. **Финальный аудит**
   - Проверить отсутствие старых неоновых цветов, толстых рамок и жёстких теней.
   - Проверить стабильные `testTag` и ключевой путь «выбор файла → обработка → расшифровка → экспорт JSON».
   - Обновить документацию дизайна и сохранить итоговые скриншоты.

## Критерии приёмки

- Все экраны используют Quiet Spruce и не содержат старого нео‑брутализма.
- Основной текст и контролы проходят заявленный контраст.
- Нет обрезанных ключевых действий при ×1,6 и в поддерживаемых ориентациях.
- Тесты и сборка завершаются успешно; непроверенные сценарии явно перечислены.
- Рабочая копия находится только в текущем workspace; исходный проект не изменён.
