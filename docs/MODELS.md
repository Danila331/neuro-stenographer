# Модели

Все модели открытые, загружаются только из официальных источников (GitHub k2-fsa/sherpa-onnx, Hugging Face
`csukuangfj/*`, `ggml-org/*`) и лежат внутри APK. Конфиги вариантов — `config/tiers/*.json`.
Полные sha256, размеры и URL: `config/models.json` (реестр, 50 записей; поле `tiers` — в какие варианты входит).

## Почему GigaAM v3 RNNT с пунктуацией

Сравнение на ПК (Mac M3 Pro, sherpa-onnx, int8, 4 потока), **тестовые** части наборов, WER в %.
Источник: `src/eval/bench_asr/results/final/SUMMARY_ru.md` (dev-части там же), память — `final/mem.jsonl`
(чистый процесс, чанк 25 с, пик RSS).
«Знаки» = `pc_sep_num`: знаки и регистр учитываются (е=ё), числа словами. «Без знаков» = `norm_num`.

| Модель | ru-asr-dev (фразы), без знаков | диалоги synth, без знаков | диалоги cats, без знаков | synth, знаки | cats, знаки | Пик RSS |
|---|---|---|---|---|---|---|
| **GigaAM v3 RNNT punct** | 7,18 | 16,77 | 22,96 | **30,83** | **32,54** | 483 МБ |
| GigaAM v3 RNNT | 5,63 | 17,57 | **20,08** | 45,86 | 54,65 | 480 МБ |
| GigaAM v3 CTC punct | 7,39 | 17,46 | 25,09 | 33,18 | 40,14 | 470 МБ |
| GigaAM v3 CTC | 5,84 | 19,91 | 23,34 | 47,43 | 56,52 | 467 МБ |
| GigaAM v2 CTC | 6,15 | 18,09 | 24,34 | 46,31 | 57,94 | 867 МБ |
| Zipformer-ru (int8) | 9,58 | 23,74 | 26,85 | 49,66 | 58,99 | 635 МБ |
| Parakeet-TDT-0.6B v3 (мультиязычная) | 14,70 | — | — | 24,93 (ru-asr-dev) | — | 1503 МБ |
| FastConformer multi CTC | 15,56 | — | — | 28,24 (ru-asr-dev) | — | 712 МБ |

Выводы:
- GigaAM v3 лучшая на русской речи: на фразах WER 5,6–7,4 % против 9,6 % у Zipformer и 14,5–15,6 % у мультиязычных моделей; на диалогах лучшая или в пределах 3 п.п. от лучшей.
- Решающий фактор — **знаки**: жюри ответило, что пунктуация входит в оценку, интонация — эталон, е/ё не различаются
  (Q13, Q14, `docs/team/BACKLOG.md`; трактовка «знаки входят в WER» — вывод из контекста, B27 не подтверждён). Модель со встроенной пунктуацией даёт 30,8 % против 45,9 % на synth и 32,5 % против 54,7 % на cats.
- Цена: без учёта знаков на cats 22,96 против 20,08 (+2,9 п.п.). Если жюри знаки не считает, мы теряем ~3 п.п. WER.
- Модель пишет числа цифрами; если эталон жюри словами, потеря ≈5,5 п.п. (B29). Режим «числа → слова» готов, решение после ответа жюри (B27).
- Скорость: RTF 0,023 (чанк 25 с, 4 потока, ПК, относительная величина: машина была загружена); Whisper-turbo — 0,211.

Параметры: чанк 25 с — компромисс (30 с точнее на 0,5 п.п., но пик RSS +60 МБ; `bench_asr/results/chunk_cats_dev.jsonl`), порог VAD 0,30 с дозабором тихой речи (`vad.rescue`; на телефонной записи WER 42,5 → 32,9 %, B42), `blank_penalty` 1,0 (полный dev WER 22,6 → 21,9 %, DER 16,0 → 14,6, B55), слова — по токенам с временем (метки: `src/eval/refpipe/README.md`).
Английский: Parakeet-TDT-110m — WER 6,64 % (FLEURS en, 200 фраз) против 9,93 % у FastConformer multi-RNNT и 12,43 % у Moonshine base
(`results/matrix_en.md`). Определение языка Whisper-tiny: точность 96 % (ru) / 99 % (en) на 10 с, 89,5 % / 97 % на 2 с
(`final/lid_full.jsonl`); в смешанных диалогах определение по первым 10 с файла верно в 40 % файлов (n=5), по фрагментам — 83–100 %,
поэтому язык определяется по каждому фрагменту (B30, `language.per_chunk`).

## Что отвергнуто и почему

| Решение | Результат | Причина |
|---|---|---|
| Zipformer-ru | WER 9,58 % против 5,63 % на фразах, 26,85 против 20,08 на cats; без знаков (59 % со знаками) | быстрее (RTF 0,008), но вдвое хуже по точности |
| Whisper large-v3-turbo вторым проходом | один turbo — 9,77 % против 4,19 % у GigaAM (166 фраз ru-dev); перераспознавание 10 % наименее уверенных фраз — 4,86 % (хуже основной); оракул 3,63 % — только верхняя граница | пик RSS 2,7 ГБ, RTF 0,21; выбор фраз по уверенности не работает (`final/second_pass_rudev.md`, `final/mem.jsonl`) |
| Несколько ASR + голосование (ROVER) | 3,80 % против 4,19 % у одной модели (GigaAM+Whisper-turbo+GigaAM CTC) | −0,4 п.п. за кратный рост времени и памяти |

| Мультиязычная одна модель (Parakeet v3, FastConformer) | 14,70 % и 15,56 % на ru-dev | втрое хуже русского GigaAM; v3 — 1,5 ГБ |
| Hotwords («Котовице», имена) | на диалогах cats 26,0 % против 29,0 % без них (лучший режим) | работают только на RNNT без пунктуации, с punct-моделью невозможны (B23) |
| Пунктуация LLM | F1 знаков Qwen3-0.6B 0,75 против 0,86–0,88 у RUPunct (llm-bench, предв.); с LLM на пути обработки пик PSS 2,1 ГБ и RTF 0,75 против 0,5 ГБ и 0,33 (эмулятор jury-4g, ранний замер 2026-11-07; без LLM сейчас RTF 0,50–0,57 из-за LID по фрагментам) | модель со встроенными знаками точнее, быстрее и не меняет слова; LLM вынесена из основного пути |

| Шумоподавление/AGC/dpdfnet на дальнем поле | не помогает или вредит (B55) | остаток ошибок — предел модели; включён только `blank_penalty` |
| Диаризация sherpa «как есть» (кластеризация чанков) | DER ±.25 25,3 % (dev), число говорящих угадано в 33 % | заменена диаризацией по фразам (ниже) |

## Диаризация, живая расшифровка, поиск, LLM

**Диаризация по фразам** (B46): эмбеддинг говорящего считается на каждую фразу ASR, затем иерархическая кластеризация (ward) и выбор числа говорящих по силуэту;
pyannote даёт только точки смены. Сквозная метрика (слова ASR × turns → Aligner → `stenoeval`), источник `src/eval/bench_diar/results/SUMMARY.md`:

| Метод | DER ±.25 dev (84 файла) | DER ±.25 test (26) | число говорящих угадано, test | cpWER test |
|---|---|---|---|---|
| sherpa штатный (было) | 25,3 % | 25,3 % | 35 % | 56,8 % |
| hybrid, CAM++ (lite) | 16,0 % | 14,2 % | 81 % | 36,9 % |
| hybrid, ERes2Net base 200k (medium) | 15,2 % | 13,1 % | 77 % | 35,8 % |
| hybrid, ERes2Net v2 (hard) | 14,9 % | 12,3 % | 88 % | 35,2 % |
| потолок (идеальные turns) | 10,3 % | — | — | — |

Размер эмбеддинга растёт с вариантом (28 → 40 → 71 МБ), скорость на фразу: 0,005 / 0,011 / 0,019–0,022 RTF (ПК, 4 потока); `window_shift_ratio` 1,0 ускоряет сегментацию ×10 при том же DER.
Итог refpipe medium на другом наборе — `docs/TEST_RESULTS.md` (test DER 24,0 → 11,7 %).

**Живая расшифровка:** потоковый Zipformer small ru (28,6 МБ, Apache-2.0) даёт только набросок без знаков и говорящих; RTF 0,055 на эмуляторе, модель выгружается до полной обработки (B13).

**Эмбеддинги AI-поиска** (`src/eval/bench_rag/README.md`, ASR-корпус, окно из 3 ходов, hit@5 / MRR): USER2-small (33 МБ int8, 384) 0,95 / 0,82;
rubert-tiny-turbo (27 МБ, 312) 0,95 / 0,78; e5-small (112 МБ) 0,95 / 0,81. Выбраны два компактных (MIT и Apache-2.0); гибрид BM25 + эмбеддинги + RRF: hit@5 0,84 на ходах против 0,77 (BM25) и 0,80 (плотный). На устройстве (jury-4g): индексация записи 1,2 с, запрос 6–29 мс (`artifacts/test-results/prerelease2/README.md`).

**LLM:** кандидаты Qwen3 0,6B/1,7B/4B (Apache-2.0, русский, GGUF в llama.cpp); размер выбран по памяти 4 ГБ (B19: Qwen3-0.6B Q8 даёт ~1,5 ГБ пик из-за repack).
Флаги памяти (`no_repack`, flash attention, KV q8_0): пик RSS Qwen3-1.7B на хосте 2,71 → 1,64 ГБ, время запроса ×2–2,5 (B48, `artifacts/test-results/llm-integration/`).
Протокол «по фрагментам + слияние в коде»: полнота 0,19 → 0,69 на длинной записи (B48). Выжимка (1.7B): атрибуция говорящих 0,98, ссылки на реплики 100 % валидны после проверки (B50, `bench_rag`).
