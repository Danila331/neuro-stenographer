# Архитектура решения

Внутренние контракты и история решений команды — `docs/team/ARCHITECTURE_TEAM.md`, `docs/team/BACKLOG.md`.

## Контекст

Android-приложение превращает запись разговора в расшифровку с говорящими и временными метками полностью на устройстве
(ARM64, ориентир 4 ГБ RAM, без сети). Результат — JSON строго по ТЗ (`config/transcript.schema.json`), просмотр с плеером,
правка, дополнительные форматы (TXT, SRT, VTT, PDF), протокол заседания, вопросы по тексту, выжимка по темам и AI-поиск на локальной LLM.
Приоритеты по оценке: точность ASR (WER) > диаризация > метки времени > скорость > UX.

## Компоненты

| Компонент | Что делает | Технология |
|---|---|---|
| `:core` (чистый Kotlin) | типы, оркестратор, выравнивание (Aligner), переразметка говорящих по фразам, защита текста (Guard), экспорт JSON/SRT/VTT/TXT/PDF-раскладка, планировщик ресурсов, живая сессия | Kotlin/JVM |
| `:audio` | декодирование любого формата → моно 16 кГц, запись с микрофона | MediaCodec |
| `:engine-sherpa` | VAD, ASR (офлайн и потоковый), определение языка, сегментация и эмбеддинги говорящих | sherpa-onnx, ONNX Runtime, int8 |
| `:engine-llm` | протокол заседания, вопросы, выжимка, ответы поиска | llama.cpp (JNI), GGUF, CPU |
| `:engine-embed`, `:store-objectbox` | AI-поиск: эмбеддинги текста, векторное хранилище (запасной путь — в памяти) | ONNX Runtime int8, ObjectBox HNSW |
| `:app` | экраны, плеер, дорожка говорящих, правка, повторная обработка фрагмента, менеджер моделей, фоновая обработка | Jetpack Compose |
| `src/eval` | метрики, Python-эталон на тех же моделях и конфиге, датасеты, бенчмарки | Python |

Один код, четыре варианта: lite / medium / hard (разные LLM и эмбеддинги говорящих) и online (без моделей). Конфиг варианта
`config/tiers/<вариант>.json` читают и приложение, и Python-эталон: параметры, подобранные на ПК, переносятся на телефон (паритет 0,00 п.п.).

## Схема обработки

```
Файл (SAF / VIEW / SEND) или микрофон  (при записи — живой набросок потоковой моделью)
  → Декодер            моно, 16 кГц
  → Нормализация       peak по файлу; усиленная копия — только для LID и ASR
  → VAD (Silero 0,30)  + rescue: энергетический дозабор речи, которую VAD не слышит
  → Упаковка чанков    границы — середины пауз, ≤ 25 с
  → LID (Whisper-tiny) язык каждого чанка + сглаживание: ru → GigaAM v3 RNNT-punct, en → Parakeet-110m
  ├→ ASR               слова с абсолютным временем, знаки и регистр, tiny-drop, strip_dashes
  └→ Диаризация        pyannote-seg-3.0: точки смены говорящего
  → Говорящие по фразам  эмбеддинг на фразу → ward + силуэт (k = 2…6, защита от монологов) → turns
  → Aligner            слово → говорящий с max пересечением, сборка реплик
  → Экспорт            JSON по ТЗ + расширенный JSON + маркер; автосохранение в Android/data/<pkg>/files/results/
  → LLM (по кнопке)    протокол по фрагментам + слияние, вопросы, выжимка (JSON по GBNF-грамматике, ссылки на реплики
                       проверяются) — после сохранения JSON
→ AI-поиск           BM25 + эмбеддинги + RRF, фильтр говорящего → фрагменты → ответ ИИ со ссылками
```
ASR и диаризация идут параллельно; эмбеддинги грузятся после их выгрузки; ASR и диаризация выгружаются до LLM. Повторная обработка фрагмента —
тот же пайплайн на отрезке. Сбой вспомогательной стадии даёт предупреждение и запасной путь; фатальны только декодирование и ASR.

## Ключевые решения

| Решение | Почему (цифры, источник) |
|---|---|
| GigaAM v3 RNNT с пунктуацией | WER со знаками 30,8 % (synth) и 32,5 % (cats) против 45,9 % и 54,7 % у версии без знаков; пик RSS 483 МБ (`docs/MODELS.md`) |
| Диаризация по фразам | test DER ±.25 24,0 → 11,7 %, число говорящих верно у 42 → 77 % файлов (`refpipe-medium-relabel-test`, `docs/TEST_RESULTS.md`) |
| VAD rescue, нормализация только для ASR, `blank_penalty` 1,0 | dev WER 24,4 → 21,9 %, затем WER 22,6 → 21,9 и DER 16,0 → 14,6 (B42, B55) |
| LLM вне основного пути | знаки ставит ASR; обработка 0,5–0,66 ГБ PSS, RTF 0,075–0,133 на release-APK (jury-4g, `artifacts/test-results/prerelease2/README.md`); с LLM-пунктуацией было 2,1 ГБ и RTF 0,75 (ранний замер) |
| Флаги памяти llama.cpp | пик RSS Qwen3-1.7B 2,71 → 1,64 ГБ (B48); на jury-4g протокол 1,71 ГБ PSS |
| Выжимка и поиск | выжимка: GBNF-грамматика, ссылок мимо 0 % против 26 % без неё; сначала версия без ИИ (`bench_rag`); поиск: hit@5 0,95, запрос 6–29 мс на устройстве |
| Модели внутри APK | автопроверка — «чёрный ящик» (Q9–Q10); менеджер моделей — дополнительный UX (скачать, удалить встроенный, восстановить) |
| Только arm64-v8a, CPU по умолчанию | жюри: ARM-эмулятор (Q6); NNAPI/GPU — только опция с откатом |
| Python-эталон + паритет | Android совпадает с эталоном по WER и DER до 0,00 п.п. |
| Язык по чанкам | по первым 10 с файла смешанные диалоги определялись верно в 40 % случаев, по чанкам 83–100 % (`bench_asr/results/final/lid_mixed.jsonl`) |
| Доступ автопроверки без UI | `ACTION_VIEW`/`ACTION_SEND`, автосохранение JSON и маркер готовности (B3, B32) |

Финальная регрессия release-APK: 16/16 PASS, RTF 0,075–0,133, 30 минут записи без OOM (`artifacts/test-results/prerelease2/README.md`).

## Зависимости

Модели (источник, версия, sha256, лицензия) — `docs/MODELS.md`, `config/models.json`. Библиотеки: sherpa-onnx (Apache-2.0), llama.cpp (MIT),
Jetpack Compose/Material 3, WorkManager, ObjectBox (API Apache-2.0, нативная библиотека закрытая, B56). Лицензии всех компонентов — `docs/LICENSES.md` и экран «Лицензии и модели» в приложении. Инструменты сборки: JDK 17, Android SDK 36, NDK 28, Gradle 9.6 (`src/android/README.md`).

## Безопасность и приватность

- Разрешение INTERNET нужно **только** менеджеру моделей; загрузка — по действию пользователя, HTTPS, проверка sha256.
- Модули обработки (`:core`, `:audio`, `:engine-*`) не содержат сетевого кода: проверяет `ArchitectureGuardTest`
  (исходники, зависимости, разрешения манифеста). Работа без сети показана в видео демонстрации (`artifacts/demo/README.md`).
- В интерфейсе пометка «Обработка выполняется на устройстве»; демонстрация — в режиме полёта.
- Аудио, расшифровки и правки — в приватной папке приложения (`allowBackup=false`); наружу — только по явному экспорту
  через системный выбор файла и автосохранение результатов в папку приложения для автопроверки.
- Микрофон запрашивается только на экране записи, по нажатию; аккаунтов нет.
