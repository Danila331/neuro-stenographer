# Архитектура решения (чистовик для жюри)

> Черновик технического писателя; источник — `docs/ARCHITECTURE.md` и `docs/BACKLOG.md`. Переносит архитектор.

## Контекст

Android-приложение превращает запись разговора в расшифровку с говорящими и временными метками полностью на устройстве
(ARM64, ориентир 4 ГБ RAM, без сети). Результат — JSON строго по ТЗ (`config/transcript.schema.json`), просмотр с плеером,
правка, дополнительные форматы, протокол заседания и вопросы по тексту от локальной LLM. Приоритеты по оценке:
точность ASR (WER) > диаризация > метки времени > скорость > UX.

## Компоненты

| Компонент | Что делает | Технология |
|---|---|---|
| `:core` (чистый Kotlin) | типы, оркестратор, выравнивание слов и говорящих (Aligner), защита текста (Guard), экспорт JSON/SRT/VTT/TXT, планировщик ресурсов | Kotlin/JVM |
| `:audio` | декодирование любого формата → моно 16 кГц, запись с микрофона | MediaCodec |
| `:engine-sherpa` | VAD, ASR, определение языка, диаризация | sherpa-onnx, ONNX Runtime, int8 |
| `:engine-llm` | протокол заседания, вопросы по тексту | llama.cpp (JNI), GGUF, CPU |
| `:app` | экраны, плеер, правка, менеджер моделей, фоновая обработка | Jetpack Compose, Material 3 |
| `src/eval` | метрики, Python-эталон на тех же моделях и конфиге, датасеты | Python |

Один код, четыре варианта: lite / medium / hard (разные LLM) и online (без моделей, скачивает набор). Конфиг варианта
`config/tiers/<вариант>.json` читает и приложение, и Python-эталон: параметры, подобранные на ПК, переносятся на телефон.

## Схема обработки

```
Файл (SAF / интент) или микрофон
  → Декодер            моно, 16 кГц float
  → VAD (Silero)       речевые интервалы
  → LID (Whisper-tiny) язык каждого фрагмента: ru → GigaAM, en → Parakeet
  ├→ ASR               чанки ≤ 25 с (границы — паузы) → слова с временем, знаки и регистр
  └→ Диаризация        pyannote-3.0 + CAM++ + кластеризация → turns          (параллельно с ASR)
  → Aligner            слово → говорящий с max пересечением, сглаживание, сборка реплик
  → Guard              слова никогда не добавляются и не теряются
  → Экспорт            JSON по ТЗ + расширенный JSON; автосохранение в Android/data/<pkg>/files/results/
  → LLM (по кнопке)    «Протокол заседания», вопросы — после показа результата, не влияет на RTF
```
Модели загружаются по очереди, ASR и диаризация выгружаются до запуска LLM; при нехватке памяти нагрузка снижается, но не падаем.
Сбой вспомогательной стадии (шумоподавление, VAD, LID, диаризация) даёт предупреждение и запасной путь; фатальны только декодирование и ASR.

## Ключевые решения

| Решение | Почему (цифры, источник) |
|---|---|
| GigaAM v3 RNNT с пунктуацией | WER со знаками 30,8 % (synth) и 32,5 % (cats) против 45,9 % и 54,7 % у версии без знаков; пик RSS 483 МБ (`docs/MODELS.md`) |
| LLM вне основного пути | с LLM-пунктуацией пик PSS 2,1 ГБ и RTF 0,75, без неё 0,5 ГБ и RTF 0,33 в раннем замере, сейчас 490–514 МБ и RTF 0,50–0,57 с LID по фрагментам (эмулятор jury-4g, 2026-11-07); жюри допускает любые локальные средства (Q11) |
| Модели внутри APK | автопроверка — «чёрный ящик» (Q9–Q10); менеджер моделей — дополнительный UX (скачать, удалить встроенный, восстановить) |
| Только arm64-v8a, CPU по умолчанию | жюри: ARM-эмулятор (Q6); GPU/NNAPI — только опция с откатом |
| Python-эталон + паритет | Android совпадает с эталоном на файлах до 0,00 п.п. WER (B28), проверка `parity.sh` |
| Язык по фрагментам | по первым 10 с файла смешанные диалоги определялись верно в 40 % случаев, по фрагментам 83–100 % (`bench_asr/results/final/lid_mixed.jsonl`) |
| Доступ автопроверки без UI | `ACTION_VIEW`/`ACTION_SEND` + автосохранение JSON и маркер готовности (B3, B32) |

## Безопасность и приватность

- Разрешение INTERNET нужно **только** менеджеру моделей; загрузка — по действию пользователя, HTTPS, проверка sha256.
- Модули обработки (`:core`, `:audio`, `:engine-*`) не содержат сетевого кода: проверяет `ArchitectureGuardTest`
  (исходники, зависимости, разрешения манифеста). TODO(финал): приложить инструментальный прогон обработки при отключённой сети.
- В интерфейсе пометка «Обработка выполняется на устройстве».
- Аудио, расшифровки и правки — в приватной папке приложения (`allowBackup=false`); наружу — только по явному экспорту
  через системный выбор файла и автосохранение результатов в папку приложения для автопроверки.
- Микрофон запрашивается только на экране записи, по нажатию; аккаунтов нет.
